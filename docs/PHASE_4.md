# Phase 4 — Controlled first-year comparisons (LL-10)

Measurement only. No balance constants, catalog quantities, rewards or starting resources changed. Full tables: `PHASE_4_COMPARISONS.md`, regenerated by

```
npm run sim -- compare --md docs/PHASE_4_COMPARISONS.md --json runs.json
```

## Method

Start greenfield, two adults, 365 days. Every variant follows the same tutorial route (each quest's own steps once, when it becomes current; a regression test proves this plays the identical game to the pacing gates' `tutorialFollower`). Each comparison changes one decision on a fixed day. The three sites (front range, Laramie, Asheville) run once in Standard (average climate) and with real-weather seeds 1–3, so 3 + 9 runs per variant. "Tutorial off" replays the tutorial run's own player actions on the same days with the tutorial skipped, so only the gifts differ. Every run uses the rules a new game in the app gets (`safeRecovery` and `reuseIdleLabor`, see below); the recorded winter save is continued with the same settings, as loading it in the app does.

## Baseline: one viable Standard first-year route exists, with almost no margin

The tutorial route survives year 1 everywhere: 0/3 Standard and 0/9 real-weather runs send anyone to town. Lowest wellbeing is 74 (65 in the worst real-weather run), and there are about 2 essential-shortage days. Home-grown food is about 20% of the food eaten.

The cash runway is the weak point. Cash falls almost monotonically from $8,000 to a median of about $430 at day 365 (range −$22 to $681). The pantry ends at 0–9 days. Every year-1 failure below is the same mechanism once cash reaches zero: the standing grocery order stops, food falls to zero months later, and the household leaves.

## Defects and questions found

1. **A stalled job held labor it never used — fixed (engine 0.4.0).** `laborPool` reserves upkeep labor for every Labor request before allocation shows which systems can run. A Part-Time Job with no Transportation got its full share, used none of it, and the hours were discarded: 2.86 h/day (20 h/week ÷ 7) less worked, and the heater 60 days later (day 85 vs 25) with identical totals. Fix: a new step after consumption (`reuseIdleLabor`, `time/step.ts`) gives granted-but-unused upkeep hours to jobs still short that day, in priority order (resident construction, then gathering, which lands for tomorrow). It never takes labor from anything and never adds crew hours. It applies to any curtailed system (a filter with no water), not only jobs. It is gated by `settings.reuseIdleLabor`, like `safeRecovery`: new games enable it, legacy logs replay unchanged (both playtest digests and all committed time digests are unchanged), and continuing an old save appends one settings action. Regression tests: `accounting.test.ts` ("labor held for a system that cannot run is not lost"); pacing passes under the new rules on all 3 sites × 3 seeds.
2. **Cash goes slightly negative** (as low as −$62) in several runs. Check whether backstops or bills are intended to overdraw, or whether purchase stopping should cap at zero.
3. **Starter shelter covers 56% of the two-adult shelter need** throughout the baseline without crossing the survival threshold. Confirm whether that is intended for a starter tent.

## Recommended next balance patch

Following the roadmap's lever order:

1. Decide the negative-cash rule (lever 1; the stalled-job labor leak is fixed).
2. Separate employment from system upkeep in work priorities, or warn when a job will displace upkeep for survival systems, before touching wages (lever 3).
3. Then set the cash/gift question as one decision: either make the no-gift route viable (starting supplies or cash, lever 6), or label tutorial gifts as the assistance they are and teach the cash runway (lever 7). The comparisons show any non-tutorial spend of about $500 or more currently tips a Standard year into collapse.
4. Re-price the outside crew only after 1–3, using the `rescue` comparison as the check.

Limits: one start, two adults, bot policy (not a novice). The release gate's novice-discoverability check still needs a human playtest.
